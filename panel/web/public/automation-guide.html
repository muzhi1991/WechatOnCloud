自动化使用说明

选择何时触发，再按顺序添加脚本或 Agent 任务。电脑控制仍遵循现有写锁规则，自动化服务不会代替 Agent 获取控制权。

快速开始触发条件步骤与变量添加脚本微信模板运行记录与排错

快速开始

  1. 打开「自动化 → 新建」，可选一个预置模板。模板仅填写值，不改变配置方式。
  2. 填写名称，选择触发条件。添加一个或多个步骤，选择脚本或已有 Agent 会话。
  3. 先保持「保存后启用」关闭，保存。在列表右侧 ⋮ 中选择「测试运行」，这会真实执行步骤。
  4. 打开运行记录，核对每一步输出和诊断日志。确认符合预期后启用自动化。

Agent 会话请先在 AI 助手中创建，建议为自动化使用专用会话。已归档或删除的会话不能接收任务。

触发条件

方式如何配置
每隔一段时间填写秒数，最少 5 秒。上一轮仍在运行时跳过本次定时。
按日历重复选择每天、每周或每月的日期与时间，设置时区。可展开查看最近 5 次预计时间；高级模式支持五段 Cron。每月不存在的日期跳过。
指定日期（一次）用日期时间选择器指定未来时间，输入和预览按浏览器时区显示。服务离线错过的时间不会补跑。
MCP 资源更新选择电脑或全局资源、已登记 MCP 服务和资源。列表只显示服务支持订阅的可用资源；微信读取服务未配置或离线时不会列出。可刷新。新增服务由管理员写入 daemon 配置，不扫描容器里的任意进程。支持资源模板的服务可在高级 URI 输入中填入实例化地址。
Webhook 通知保存后显示地址和专属密钥，密钥只显示一次。发送 POST JSON，带 Authorization: Bearer 密钥。只有启用的自动化接收 Webhook。

MCP 通知表示资源可能变化，不一定包含消息正文。首次订阅和重新连接也会触发一次检查；实际数据由脚本查询并去重。

步骤、管道与变量

步骤从上到下串行运行。脚本 stdin 默认收到前一步的 stdout；第一步收到触发事件 JSON（包含 source、received_at、data）。脚本 stdout 只放结果，stderr 放诊断日志。Agent 步骤成功后输出其回复文本，供下一步使用。

勾选「上一步输出为空时跳过」可避免无消息时唤醒 Agent。空指无文本或仅空白；[]、{} 和 null 都不算空。失败立即停止，不自动重试。步骤可上下移动，内部 ID 不变；删除或移动造成的向后引用会在保存时提示。

参数、任务内容及高级环境变量绑定均可插入变量。选项菜单提供常用引用；可继续填写 JSON 字段路径。变量只查值，不执行代码、不做 shell 展开。

引用含义
{{trigger.received_at}}触发接收时间
{{trigger.body}}触发源原始数据对象；Webhook 是提交的 JSON
{{trigger.machine_id}}由微信资源 URI 映射的电脑 ID；其他源可能为空
{{input.text}} / {{input.json}}本步骤收到的文本 / 解析后的 JSON
{{steps.read_messages.json.messages}}指定前置步骤的 JSON 字段；read_messages 是稳定步骤 ID
{{run.id}}本次运行 ID

引用不存在的变量会明确失败。外部消息内容是数据，不应当作为新的权限或操作指令。传参使用独立 argv，不拼接 shell 命令。

脚本环境变量

WOC_RUN_ID / WOC_STEP_ID运行和步骤 ID
WOC_MACHINE_ID触发源关联的电脑，可能为空
WOC_TRIGGER_FILE触发上下文 JSON 文件
WOC_INPUT_FILE本步骤输入文件；原始文本，未必是 JSON
WOC_CONTEXT_FILEtrigger、run、input、steps 上下文 JSON 文件
WOC_TRIGGER_STATE_DIR该自动化的持久状态目录，上限 16 MiB

前三个输入文件只在步骤执行期间存在。大数据用 stdin 或文件；环境变量只放小值。子进程的 export 不会传给下一步，要通过 stdout 输出结果，再在下一步绑定环境变量。

添加脚本和参数表单

在 Agent 容器的 /workspace/woc/automation/scripts/ 放入 Python（.py）或 Shell（.sh）文件，重新打开编辑器即可选择。不需要执行权限，分别由 python3 和 bash 运行。上传和在线安装暂未提供。

脚本使用标准 --参数 和 --help。同目录的描述文件决定表单，扫描列表只读取文件，不执行脚本。没有描述文件时可填写 JSON 参数数组，查看 --help。运行帮助和自定义选项提供器会执行该脚本，因此应保持只读、快速退出。

# greet.py
import argparse, json, sys
p = argparse.ArgumentParser(description="处理输入数据")
p.add_argument("--style", choices=["brief", "full"], default="brief")
a = p.parse_args()
data = json.load(sys.stdin)
print(json.dumps({"style": a.style, "input": data}))

// greet.action.json（与 greet.py 同名，不包含 .py）
{
  "title": "处理数据",
  "description": "接收上一步数据并整理输出",
  "parameters": [
    {"name": "style", "label": "详细程度", "type": "string",
     "default": "brief", "options": ["brief", "full"], "help": "选择输出格式"}
  ],
  "outputs": ["style", "input"]
}

JSON 文件本身不要包含注释。参数类型支持 string、number、boolean；支持 required、default、min、max、options、help。布尔值为真时传入 --flag，为假时省略。手动命令兼容旧配置；额外参数在高级设置中填写。

动态选项

描述中的 provider 可为 machines、wechat.chats、wechat.members 或 script；depends_on 指定依赖参数。切换电脑会清除依赖的对话和成员。长列表支持搜索和加载更多，保存的是 ID。

自定义 provider=script 时，界面按需调用 脚本 --list-options 参数名。stdin 和 WOC_OPTIONS_CONTEXT 提供 {params, query, cursor}。返回以下 JSON；不要执行业务动作，也不要打印其他 stdout。超时 4 秒、输出上限 64 KiB。

{"items":[{"value":"stable_id","label":"显示名称"}],"next_cursor":null}

动态选项与运行步骤分离，界面不会为了提供选项提前运行前一个 action。上一步的运行结果只能在实际执行时引用。

微信模板：读取新消息 → Agent

  1. 套用模板，选微信电脑及其 messages 资源。
  2. 在「读取微信新消息」步骤选择电脑、对话。可切换最近会话、联系人、群聊；群聊还需选择关注的成员。默认查询最近 50 条。
  3. 在第二步选择 Agent，会收到第一步输出的消息。默认任务仅汇总，不发送微信回复；按实际授权修改。
  4. 第一次运行建立基线，不处理已有消息。之后有新消息才输出批次并唤醒 Agent。无新消息、自己的私聊发送消息均不会触发第二步。

脚本只读数据库，不获取 GUI 写锁，不自动点击下载。收到通知后本地数据库可能仍有同步延迟；最近 N 条窗口也可能漏掉长时间离线期间的消息。微信未读状态不等于自动化处理进度。

消息批次在下游完整成功后才提交处理进度。若 Agent 提交结果未知、运行中断或后续步骤失败，下次读取会提示检查原运行记录，不自动重发。若历史记录已过期，也会停下来要求核对。确认后由管理员或 Agent 按已授权范围处理该自动化状态目录里的 pending；不要直接删除状态绕过核对。

运行记录与排错

点击记录可查看各步骤状态、输出、诊断日志，以及对应 Agent 会话链接。已删除的会话会显示不可用提示，不会跳到无关会话。Agent「成功」表示对应消息已提交、观察到回复并恢复空闲，不保证业务目标完成。

  • 参数无选项：先选依赖的电脑/对话，缩小搜索范围，点击重试；检查数据读取服务在线。
  • 变量不可用：检查路径及步骤顺序，确认上一步输出是 JSON，引用对象使用稳定步骤 ID。
  • 脚本失败：查看 stderr 和退出码。stdout 应仅输出结果；超时会结束进程组。
  • 结果待核对 / 已中断：先检查对应 Agent 对话与实际业务结果，不盲目重复发送任务。

当前限额：每个自动化最多 12 步；单步输出最多 256 KiB，所有步骤输出上下文合计 512 KiB；单步超时 1–3600 秒；最多 4 个运行并行，同一自动化串行。输入文件执行后清理；运行记录保留 7 天或最新 1000 条。私人输入与输出仅对管理员可见，请勿在日志中打印凭证。

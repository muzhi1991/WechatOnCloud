# 用户级控制权、协商申请与只读界面

日期：2026-10-30。本方案取代此前“标签页拥有控制权、人工普通申请直接强制接管”的行为。作用范围是当前统一控制台中的受管实例；原非受管 WOC 旧模式没有这一协商协议。

## 身份和一把锁

机器 ID 唯一标识控制对象，每台机器仍只有原 ControlLeases 的一把 GUI 写锁。人工持有人由认证 Cookie 解析的用户 ID 决定：`human / user:<id>`。相同用户的浏览器标签页、刷新或其他已登录设备共享该用户的控制权。旧 `x-woc-client`/wocClient 参数作为兼容连接标记保留，不再决定所有权；客户端不能通过这个参数冒充其他用户。

Agent 仍由 Bearer 凭证对应到稳定 client ID；原 Cua、woc-daemon、微信业务接口的鉴权和同一把写锁保持原逻辑。epoch 代表一次控制周期，写入、释放、批准申请仍检查它，防止旧页面的延迟操作影响新持有人。

同一用户多个页面可以同时持有同一用户的控制权；共享身份内的交错操作不在本次方案中另建锁。用户之间的交接则必须通过下列申请协议。

## 最小申请模型

每台机器最多一条待处理申请，包含 request ID、申请人 Actor、当前控制周期 epoch 和 expiresAt。申请有效期 60 秒，重复提交同一人的申请返回原申请，不延长时间。没有队列、任务调度或超时自动批准。

| 当前情况 | 普通申请结果 |
| --- | --- |
| 无持有人 | 获得控制权 |
| 已由本人持有 | 返回本人控制状态 |
| 被其他人或 Agent 持有 | 创建待处理申请，原持有人继续操作 |
| 已有其他申请 | 提示已有待处理申请 |
| 交接/维护/故障 | 返回当前不可申请的条件 |

只有当前持有人能同意/拒绝，并且申请必须仍属于当前 epoch。批准前重新检查申请人的机器权限；批准使用既有交接逻辑，停止旧写入、等待在途操作完成，再授予新持有人。没有再次获取锁的循环，也没有向 daemon 回调。

申请人可取消。拒绝、取消、超时、权限撤销或控制权变化使申请失效，不自动给别人控制权。释放后新申请可以取得空闲机器；未获批的旧申请不自动接续。面板重启清空锁与待处理申请，不需要持久化新数据库。

管理员只有点击独立的“强制接管”并确认才走 force 路径；服务端也校验管理员角色。管理员点击普通“申请控制”一样需要持有人同意。普通用户不能强制接管，也不能因为是管理员就代替当前持有人点击批准；管理员需要使用明确的 force 操作。

## 接口与未来 Agent 接入

| Web HTTP | 行为 |
| --- | --- |
| GET /api/instances/:id/control | 原锁状态，新增可空 request 摘要 |
| POST /api/instances/:id/control/take | 申请；不再默认 force |
| POST /api/instances/:id/control/respond | `{request_id, approve}`；持有人 + 当前 epoch |
| POST /api/instances/:id/control/cancel | `{request_id}`；仅申请人 |
| POST /api/instances/:id/control/force | 仅管理员明确强制接管 |
| 原 beat / release | 继续按当前用户及 epoch 续期/释放 |

request 摘要包括 id、label、kind、expiresAt、mine、canRespond。网页复用原 3 秒状态轮询，无新增推送连接。待处理状态与原锁的 handover/pending 区分，申请不会把正在操作的人切到只读。

核心 [ControlRequests](../../panel/server/src/control/requests.ts) 接受通用 Actor（human/agent），依赖注入机器权限检查。已测试“人同意 Agent 后交接”的内部路径。当前生产入口只开放网页人工申请，运行时权限解析也只接人工；**未新增 Agent 主动申请或处理申请的 MCP 工具**。后续在既有 WOC MCP/HTTP 适配器接入该模型与 Agent ACL 即可，原 acquire 的立即获锁/忙错误语义不变。当前 Agent 持锁时也尚无 MCP 审批入口；网页申请不会强占它，实际交接需 Agent 交回或管理员明确强制接管。未处理申请仍按 60 秒失效，不自动批准。

代码入口：[身份](../../panel/server/src/control/actors.ts)、[申请 HTTP](../../panel/server/src/control/request-routes.ts)、[锁交接](../../panel/server/src/control/leases.ts)、[网页控制栏](../../panel/web/src/ControlStrip.tsx)。

## 不遮挡的只读体验

移除桌面中央申请卡片、遮暗和模糊。画面上方的独立控制栏显示“只读 / 谁正在控制 / 申请控制”；只读画面只保留透明输入拦截和禁用鼠标样式，服务端仍强制拒绝未经授权的输入，不能只靠前端遮罩。

收到申请时在控制栏内显示申请人和同意/拒绝按钮，不弹模态对话框、不自动聚焦、不盖住桌面。申请者可看到等待状态和取消按钮。管理员强制接管是主动操作，另外显示确认框；不会因为收到申请而弹出这个框。

人工页面每 5 秒发送连接心跳，默认 30 秒收不到心跳则交回。新增独立的人工操作空闲期限，默认 300 秒（5 分钟）。心跳、刷新、查询、重复申请不更新操作时间；桌面 iframe 内可信的键盘、鼠标移动/按下、滚轮、触摸及输入条操作才上报活动，受管 HTTP GUI 写操作也计入。活动上报按 2.5 秒节流，未发送活动保留至下一心跳，绑定当前 epoch，服务端以收到活动的时间计时（允许几秒传输/节流误差）。过期请求不能恢复原锁。

同一用户的多个页面共用服务端最后心跳和最后操作时间。关闭一个页面不代表退出所有页面；另一个页面心跳只能保持连接期限，仍须在空闲期限内有真实输入。后台页不主动停止心跳，但浏览器冻结、断网和关页都可能导致断线超时。主动交回或超时影响该用户在该机器的所有页面；页面按原 3 秒状态轮询同步只读，服务端立即撤销旧 epoch 并关闭可写 VNC 连接。

Agent 稳定客户端锁默认 120 秒无 GUI 写操作交回，查询/截图不续期，在途操作等待结束。未修改原 Cua MCP/Skill/spacesd，也未改变旧短期 token 接口的协议。

### 超时设置

管理员入口：**管理 → 系统 → 控制权超时**；普通用户设置页可查看。三个值分别为网页断线（默认 30 秒，范围 15～300）、网页操作空闲（默认 300 秒，范围 30～3600）、Agent 操作空闲（默认 120 秒，范围 1～3600），单位均为整数秒。全局应用于受管实例，非受管旧模式不变。待处理申请仍独立保留 60 秒，不是持锁时限，本次不增加配置。

`GET /api/control-timeouts` 登录可读；`POST /api/admin/control-timeouts` 仅管理员写，body 为 `{disconnectSeconds, humanIdleSeconds, agentIdleSeconds}`。保存至原 accounts.json 的 settings.controlTimeouts，使用已有临时文件＋原子替换持久化。尚未保存时 Agent 默认继承 WOC_CONTROL_IDLE_MS，保存后页面配置优先。

修改立即依据已有最后心跳/操作时间计算期限，不从保存时刻重新计时；缩短到已经超时会交回，延长不能复活已过期的锁。`control/beat` 新增可选 `{activity:true}`；仅持有人及当前 epoch 可以更新活动。原无 body 调用仍只更新心跳。

日期：2026-10-28。状态：P0 仓库准备和 P1 单实例原型已完成；在 llm-server 新建容器通过下述验收。P2～P5 尚未实现。

用户目标：保留 WOC 网页人工操作、多微信实例、文件管理和备份能力；同一实例可被 Agent 通过 Cua 接管，并运行浏览器、终端等其他应用。wxcli 是未来可选的读取模块，不是本阶段前置条件。

## 2. 首版架构和责任边界

```text
用户浏览器 ── WOC 面板 ── KasmVNC ──────────────┐
                                              ↓
                                  同一个实例、同一个 X 桌面
                                              ↑
Master Agent ── 受管 Cua 工具/控制租约 ── cua-spacesd

WOC 面板 ── 宿主 Docker ── 创建/启停/重建/删除实例
    │
    └─ 集成实例清单 ── Master 注册协调器 ── Cua Spaces 本地登记
```

- WOC 是实例生命周期唯一管理者，Cua 只登记和访问已有实例。Cua 的删除登记不应映射成删除 WOC 容器或数据卷。
- 每个 WOC 实例有自己的桌面、数据卷、Cua token 和稳定业务 ID。微信 1、TG 1、微信 2 仍是三个实例；同一实例内可以按任务启动附加应用。
- Master 初期在现有控制端运行；通过远程 Cua 执行 Shell、文件和 GUI 操作。不要求每个实例都预装并常驻完整模型 Agent harness。
- 新实例使用 WOC 派生镜像。现有 `cua-worker-01` 是已有工作环境与通用任务执行环境，不参与本轮试验迁移。
- wxcli 不进入首版依赖。UI 自动化与读库的账号风险没有可据此量化的比较结论，不承诺任何路线零风险。

## 3. 代码落点

保留上游 `docker/`、`panel/server/`、`panel/web/`。以下为整体规划；目前仅 `docker/cua/`、`deploy/cua/`、`scripts/cua/` 和文档已落地：

```text
wechat-on-cloud/
├─ docker/cua/                  # 派生 Dockerfile、s6 服务定义、运行环境和依赖检查
├─ panel/server/src/cua/
│  ├─ config.ts                 # 集成开关、固定版本、路径与端口配置校验
│  ├─ instances.ts              # token引用、稳定端口、generation、健康与能力
│  ├─ control.ts                # 人工/Agent/维护控制权与交接状态机
│  └─ routes.ts                 # 机器清单、控制权和诊断接口
├─ panel/web/src/               # 在现有实例页扩展状态、接管/交回入口
├─ integrations/cua-master-sync/ # 对账、健康检查、官方CLI登记；运行于指定Master
├─ deploy/cua/                  # 测试部署配置、无秘密的环境变量示例、版本清单
├─ scripts/cua/                 # 构建、冒烟、升级/回滚验收脚本
└─ doc/dev/Cua集成实施方案.md
```

只在现有 `docker.ts` / `index.ts` / `store.ts` 中接入必要调用，新增业务放入独立模块。集成开关关闭时保持原 WOC 行为；旧数据无 Cua 字段时按未启用处理。每个扩展字段有默认值和幂等迁移。

## 4. 镜像方案

### 4.1 派生而不替换桌面

以核验过的 WOC 实例镜像 digest 为基础构建独立派生镜像。核对镜像对应的上游 commit；若没有匹配且可验证的已发布镜像，则先从当前上游源码构建 WOC 基础产物，再在其上派生。第一阶段只验证现有服务器所需的 amd64。

镜像中添加固定版本的 `cua-spacesd` 与其实际所需系统依赖，保持 WOC 原有 s6 启动体系。Cua 当前文档中 Driver 链接于 spacesd 进程，不默认再起一个独立驱动服务。先以安装产物和 `doctor` 实测确认所需资源。

运行条件：

- Cua 使用 WOC 的桌面用户（默认 abc/配置的 UID），接入实际 DISPLAY、XAUTHORITY、D-Bus 与音频会话；不假定固定 `:1` 已足够。
- 不引入第二套 X server、XFCE 或窗口管理器。Cua 截图必须与 WOC 网页显示属于同一桌面。
- 持久状态显式放到 `/config/.cua/spacesd`；工作目录首版用 `/config/workspace`。这些目录的日志/缓存设轮转和容量边界，磁盘不足时停止新任务并显示原因。
- token 是每实例的随机秘密，独立挂载，不写进镜像或普通 accounts.json 字段；面板仅保存秘密引用。日志不输出 token。
- 新增服务失败只将 Cua 标为不可用，人工 KasmVNC 仍可使用。等 X 和会话就绪后启动 Cua，失败重试需退避。
- 不盲目复制 Ubuntu 官方 Cua 镜像中的整个文件树；在 Debian 环境核验二进制与库依赖。

### 4.2 必须调整的 WOC 行为

1. `docker/autostart` 的“每两秒激活不可见窗口”增加可控开关，Cua 模式关闭自动抢焦点；人工恢复窗口改为显式动作。
2. 主应用自动重启保留，但进入维护/升级或 Agent 有意停止应用时可以暂停；主应用崩溃与 Cua 服务崩溃分别处理。
3. watchdog 将 Agent 的运行占用纳入活跃状态；有任务时不做 soft 重启。hard/OOM/显式重启需将任务标记中断，不能自动重复发送消息。
4. 修复当前 watchdog `interval=0` 被 `Math.max(60, ...)` 覆盖的开关行为，增加语义测试。按混合负载重新确定内存阈值，不沿用微信专用默认值。
5. 镜像解析保持显式 digest；自更新、版本探测和 fallback 不得把派生实例换回上游原镜像。重启继续使用原镜像，升级才改变版本。

## 5. 自动接入 Cua Spaces

### 5.1 首版连接方式

采用现有内网/隧道拓扑，每个实例容器内部提供 3211，宿主分配独立且持久的端口。绑定地址由配置指定；实际端口范围、现有占用及 Master 到宿主的路由在部署前检查。先验证 HTTP 控制、截图等能力；需要 QUIC 时再单独规划 UDP 端口，不能假定只映射 3211 已覆盖所有媒体传输。

不把 Docker 内部 IP 或容器名直接交给远端 Mac 当连接地址；容器重建后内部 IP 可变。端口应与稳定 WOC ID 关联，重建复用，删除后经过清理再回收。

协调器运行在指定 Master，使用官方 Cua CLI 或已核实 SDK；首版优先 CLI。`cua spaces add` 完成握手后登记到这个 Master 的注册表，不代表全账户所有客户端立即出现。relay/跨设备发现放第二阶段。

### 5.2 数据和状态

在 WOC 实例元数据增加 `cuaEnabled`、`endpoint`、`hostPort`、`secretRef`、`generation`、版本和能力状态。保留稳定实例 ID，Docker container ID 只是本次运行标识。

协调器通过新增、受限的服务身份接口读取允许同步的实例清单；不直接解析面板私有 JSON，也不假设已有用户 Cookie 就是机器认证接口。凭证由部署配置下发给指定 Master 并保存在本地秘密文件，未通过秘密同步的实例保持 pending。

状态：`disabled → starting → ready → offline / error`。Cua 未就绪不会把 WOC 实例删除，也不阻止人工进入。

| 事件 | 协调行为 |
|---|---|
| 创建 | 等容器、图形会话、spacesd健康后，登记稳定名称 `woc-<id>` |
| 重启/升级 | 进入维护，更新 generation；恢复后核对 endpoint/token，原登记更新，不生成重复项 |
| 停止 | 标记不可用并停止分配任务，不删除业务身份 |
| 删除 | 确认最新 generation 已删除，再清理本协调器所属的登记 |
| 协调器重启/事件丢失 | 全量对账，只处理自身命名空间；不操作原有 cua-worker-01 |

首版定期对账即可，Docker 事件作为后续提速；不让每个容器自行登入用户 Cua 账号。登记失败可重试，删除和 token 轮换必须防旧 generation 覆盖新状态。通过 spacesd 直连的“电源操作”保持禁用或明确跳转 WOC 生命周期入口。

## 6. 人工与 Agent 控制权

### 6.1 首版保证

同一桌面一次一个 GUI 写入者，可多人观看。Agent 在其他窗口打字、启动会抢焦点的应用、改变分辨率、操作剪贴板，都算桌面写入，不能当作无冲突后台任务。不同实例可并行。

状态机：`idle / human / agent / handover / maintenance`。租约包含实例 ID、holder、到期时间、epoch；实例重建 generation 变化或控制器重启后，旧动作全部失效。不能只依赖当前 WOC 10 秒心跳软锁。

人工接管：进入 handover → 停止接纳 Agent 新动作 → 中断或等待在途动作确认结束 → 释放可能按住的输入状态 → 人工取得控制。若无法确认旧控制者已停止，显示待处理，不能声称接管成功。交回 Agent 后必须重新截图/识别目标。发送中断后先核对是否已经发出，再决定后续动作，不自动重放。

### 6.2 两条输入通路都必须生效

- WOC：type/key/paste 等 HTTP 输入接口检查同一租约；KasmVNC 的原生键鼠输入需要服务端只读/写入权限控制，并验证已有 WebSocket 会话是否即时生效。若权限变更仅对新连接生效，采用受控断开与重新建立只读连接。不能把前端遮罩作为完整保证。
- Cua：通过受管工具适配层申请/续租，每次会改变桌面的调用校验 epoch。spacesd 的原始管理 token 不直接提供给普通任务；原生 Cua MCP/CLI 接入到调度器的方式要在 P3 明确验证，不能只创建一个未经调用的“锁服务”。
- 紧急恢复保留管理员入口，并记录它会中断 Agent。本方案控制权是协作保证；拥有容器 Shell/本地 X 权限的进程可能绕过工具入口，若要求隔离不可信 Agent，需单独用户/权限/容器方案。

GUI 操作权限默认关闭，直到交接验收通过。人工控制时，Agent 可继续推理和真正不影响桌面的计算任务。长时间独立浏览器任务优先放原通用 Cua worker；需要微信动作时再借用消息实例。

## 7. 分阶段交付

每阶段一个独立可审查改动，门禁未过不进入下阶段。无需先实现完整平台才验证图形兼容。

| 阶段 | 交付内容 | 必须通过的验收 | 失败时退路 |
|---|---|---|---|
| P0 仓库与版本准备 | GitHub fork/origin、固定上游/Cua版本、构建清单；审核继承的发布和Telegram工作流 | 工作流不会向上游镜像仓库发布或触发无关通知；基线构建结果记录 | 保留当前文档与上游基线 |
| P1 单实例兼容原型 | 派生镜像、s6服务、窗口看守开关；新建不含个人登录的测试实例 | WOC与Cua同画面；窗口列表、截图、中文、剪贴板、分辨率变化；浏览器/终端切换；重建文件保留 | 删除专用测试实例；若Kasm/Cua不兼容则先诊断，不自动迁移现有微信 |
| P2 动态创建与注册 | Cua配置注入、稳定端口/秘密、集成状态、Master协调器 | 面板创建自动登记；两个实例互不串线；停启、重建、删除和协调器重启一致 | 关闭集成，人工WOC仍可用 |
| P3 控制权交接 | 服务端输入控制、受管Cua工具接入、前端接管/交回状态 | 双浏览器与Agent竞争、租约超时、断线、控制器重启、在途动作；不能混入输入 | 禁用Agent写入，保留人工操作 |
| P4 生命周期和恢复 | watchdog任务感知、维护排空、升级/回滚、备份策略 | Agent工作不被soft误重启；硬中断任务可追踪；升级不丢Cua、秘密或文件；无重复执行 | 回退兼容的面板/实例镜像；必要时恢复对应数据快照 |
| P5 微信任务试运行 | 明确授权的微信会话测试、Agent操作入口和运行记录 | 找到正确聊天对象；输入/取消；指定测试收件人发送一次并核对；人工可恢复 | 停用任务，人工继续使用 |

P1 是本计划最先应实施的代码阶段；P2 完成前可以手动注册测试实例。P3 之前的 P1 输入测试由单一操作者串行进行，不开放人机并发操作。

P5 的发送验收使用专门明确的测试收件人与内容，不能从方案批准推导对真实好友自动发消息的授权。wxcli、自动回复策略、全量聊天索引、relay和多桌面并行作为后续独立阶段。

## 8. 测试、持久化与发布

有意义的自动测试集中于：控制权状态机/epoch、重建与登记幂等、秘密引用迁移、端口分配、镜像digest保持、watchdog活跃判定。对副作用流程模拟失败和重试，不靠镜像内部“进程存在”判定成功。

代码阶段执行后端/前端 TypeScript 检查、前端构建，再执行上游实例探针和本计划的同桌面/交接验收。当前上游后端没有现成 test script，新增模块测试可使用已有 tsx 配合 Node test runner；具体命令随实现落入 package.json。UI/容器集成必须在目标 Linux 服务器验证，Mac 构建成功不能代替。

发布遵循上游门禁：CI验证产物与发布产物一致；正式功能发布前至少过夜试运行；记录上游commit、派生镜像digest、Cua版本、应用版本和回滚方法。先做 amd64 私用试运行，arm64 支持须单独验收。

备份注意：WOC整卷备份会把 `/config` 下Cua状态与工作文件一起打包。需要文档说明范围，并避免将主访问token混进普通导出。恢复同实例和克隆新实例分开处理：克隆重新生成token与注册身份；禁止两个运行实例共享同一可写微信目录。

新增日志、任务产物和Cua缓存均配置轮转/容量限制；自动清理仅针对明确标记的缓存与过期产物，不删除微信数据、用户工作成果或密钥。数据格式升级前建立匹配快照；镜像回滚不等于数据库/应用数据可自动降级。

## 9. 完成标准与本轮状态

首版完成标准：用户在WOC新建实例后，人工网页操作保持可用，Master自动看到并访问同一实例；人机交接不混入输入；其他实例不受影响；实例升级、重建与恢复有实际记录；已有通用Cua worker继续独立工作。

本轮已完成：fork/origin、固定基础镜像与 Cua 校验值、派生镜像、s6 服务、共享 D-Bus/AT-SPI、窗口看守开关、llm-server 独立测试实例、本地 Cua 登记及 P1 验收。未发布镜像或正式 release，未接入 WOC 管理面板的动态创建，未实现自动注册和控制权交接，未登录测试微信或读取聊天数据库。

P3 新增实测输入：KasmVNC 网页键入混合大小写后可能遗留 Caps Lock；必须在交接时探测并校正修饰键/锁定键状态，不能只释放鼠标。微信登录窗口未暴露 AT-SPI 树，截图路线可用；不能把浏览器辅助功能成功推断为微信聊天结构可读。
